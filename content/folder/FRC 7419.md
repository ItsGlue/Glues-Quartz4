>Role: **Robot Software, App Development,  Sensor Integration**

I participated in 4 seasons of FRC as a member of the team 7419. Along with teams 254 and 1678, we won the silicon valley regional and set the most points scored world record. The image above shows the triple hang (traversal) which helped us achieve that WR score.

The limit switch and magnetic limit switch are two sensors that might seem insignificant at first glance. They are both sensors that return a binary output depending on the state of the switch. The limit switch returns a 0 or a 1 based on whether or not the switch is pressed while the magnetic limit switch does the same thing using the Hall effect. These sensors were implemented on the elevator (for climbing) and turret (for aiming game object) respectively. Despite their simplicity, they played a crucial role in preventing mechanical parts from going past an expected position.

The beam break sensor was another sensor I used, which could detect whenever a beam was broken. This was used as a way to know whenever a game object went through the intake system (the object would break the beam).

For vision, we primarily used Limelight, which is a smart camera developed specifically for FRC. It was tuned for april tag pose estimation and for games such as rapid react we used it to auto aim at reflective tape near the scoring area. 

<div align="center" style="font-size: 1.3rem;"> * * * </div>

Devices were wired with a daisy chain topology using CAN bus. This meant not every device was connected directly to the main computational device or the power distribution panel. Instead they formed a daisy "chain" which massively simplified the wire management problem. To communicate with a specific motor controller or sensor, simply instantiate it with the device's CAN ID.
